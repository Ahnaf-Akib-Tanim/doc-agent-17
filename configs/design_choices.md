# Per-stage design choices

Team 17 · *Biodiversity & Species Knowledge Assistant* · domain **historical palaeontology monographs**
· data speciality **table/figure-heavy** · primary NFR **robust / reliable** · declared bonus
**semantic (structure-aware) chunking**.

Filled through Stage 4 for A2 (Stages 0–4 are built; 5–9 state the committed design and are built in
A3/A4). Every number cited here is produced by `notebooks/eda.ipynb` or `notebooks/kb_demo.ipynb`.

| Stage | Problem statement | Data | Model | Methods | Design | Development | Deployment | MLOps |
|---|---|---|---|---|---|---|---|---|
| **0 Frame** | Given a scanned page from four palaeontology monographs, answer a curator's question grounded in that page, with a citable page and region. Success = answer-F1 ≥ 0.70 on the verifiable subset, retention ≥ 0.90 under perturbation, worst-slice ≥ 0.60, false-answer ≤ 0.05. | 4 BHL/Internet Archive volumes, 904 page-images, 240,893 words. Split by **document**: train `lucas_1901`+`gilmore_1914`, val `colbert_1945`, test `leidy_1853`. | None — framing stage. The three axes (domain × table/figure-heavy × robust) are the model of the problem. | Pin the axes and the metric in `configs/task.yaml`; pin the corpus by SHA-256; declare the lazy baseline (top-1 chunk verbatim ⇒ answer-F1 ≈ 0.06) so value can be proven, not asserted. | `task.yaml` is the single source of the three axes; `grading_kit/manifest.yaml` is the only file a grader must open. | The floors (≥300 pages, ≥60k words) are asserted in `data/validate.py`, not checked by hand. | The framing is what fixes the read-only autonomy level and the ≤ 8-step budget carried into A3. | Corpus id `corpus_64f400d6` from `data/versioning.py` — content-addressed, so it changes iff the bytes change. |
| **1 Ingest + Enhance** | Turn 4 licensed PDFs into clean, provenance-pinned page images with per-page quality fields, without destroying the plates. Success: every kept page carries kind + band + skew + contrast; all plates survive. | In: 4 PDFs (52.5 MB). Out: 904 greyscale PNGs @150 dpi → 765 kept, 139 blank versos dropped. Labels here are **derived**, not hand-made: kind from ink geometry, band from contrast/skew/speckle. | **No trained model, deliberately.** Classical CV: PyMuPDF raster, projection-profile deskew, connected-component despeckle, Sauvola. `enhance.enabled: false`. | Deskew = maximise horizontal projection-profile variance over −3…+3° at 0.25°, applied **only** above 0.5° and **never** to a plate. Despeckle = drop components ≤ 2 px not within 3 px of a larger one (protects i/j dots). Binarize = Sauvola (31 px, k = 0.34) into a **separate** reader image. Plate test **before** blank test. | The greyscale page is never overwritten: raw → clean → reader are three files, so a citation always crops unaltered pixels. `contracts.Page` is locked to 3 fields, so measurements travel in `pages_meta.jsonl` keyed by page_id. | Thresholds set from measured distributions, not defaults (0.5° because 99% of text pages sit below it; the Otsu threshold is floored 45 levels below the paper median because Otsu "finds" 40% ink on a blank leaf). Stage cached: a re-run skips existing rasters. | Offline batch, CPU, ~10 min for 904 pages, no GPU. The same code path is what A3's `enhance_page` tool will call at query time, so a query-time re-read cannot silently differ from the index. | Every page row records `source_sha256`, dpi, skew raw **and** applied, and the three image paths — the preparation is auditable rather than silent. |
| **2 Layout** | Find text / table / figure / heading regions **and recover reading order and table structure**, because a detached row label attributes a measurement to the wrong species. This is the data-speciality stage. | 765 preprocessed pages → 3,626 regions: 3,075 text, 204 heading, 196 figure, 151 table. | `heuristic:rlsa-cc-grid` — deterministic, no GPU, no labelled layout data. DocLayout-YOLO (A1's plan) was **not** shipped: it needs layout labels for *this* corpus to beat a tuned heuristic, and we had none. | (1) figures first: close-then-open fuses halftone stipple into a solid block while type does not — mask them out; (2) column gutters from the vertical ink profile; (3) RLSA smear → lines → blocks; (4) table iff ≥ 60% of rows carry a wide internal gap **and** mean line-fill ≤ 0.55. Prose fills 0.72 of its own span on this corpus; table rows fill ~0.40. | Regions come back in column-first reading order. The grid (rows × cols), column index and reading order go to `regions.jsonl`, because `contracts.Region` is locked to `(page_id, bbox, kind)`. | Calibrated on 17 named pages spanning table / prose / plate / two-column, and **those 17 pages are excluded from the held-out slice by name**. Verified visually in `kb_demo.ipynb` §3 with boxes drawn on real pages. | ~0.1 s/page on CPU, batch. Region boxes are stored normalised so the A4 UI can highlight them over the original scan at any zoom. | `layout_model` and every threshold are recorded in `data/index/meta.json`, so an index states which detector built it. |
| **3 OCR** | Read each page, **preserving structure** — a table must come back as a table and text printed inside a figure must be transcribed, not skipped. | 765 pages in; 6,041 typed blocks / 243,916 words out. Scored against an independent second reader on all 777 non-empty pages + a 16-page held-out slice. | **Qwen3-VL-8B-Instruct** (fp16, 2×T4), a published pretrained VLM reproduced and adapted by prompt. Fallback: `microsoft/trocr-base-printed`, implemented and measured, then rejected. | Page-level structured prompt (Markdown for simple tables, HTML with colspan for wide ones, explicit blank-page rule, explicit instruction to read text inside figures). Region-level path crops the region and reads it line-by-line. Not fine-tuned in A2. | The reader's per-page output is the durable artefact; `transcribe()` replays it and falls back to region reads on a cache miss, so the index rebuilds on a laptop without re-renting a GPU. Block kind is prefixed on the text so Stage 4 can key on it. | Measured against a **different vendor's** reader as oracle and against the **IA text layer embedded in the same PDFs** as baseline: corpus-wide CER 6.20% vs 8.65%, char-F1 98.09% vs 97.11%. | Batch, GPU, ~2 s/page on 2×T4. Same `Reader` class serves A3's `read_page` tool at query time. | `ocr_model` recorded in index meta; the per-volume transcription files are the versioned artefact. Re-reading one volume invalidates only that volume's chunks. |
| **4 Index** | Make the extracted text retrievable **as the unit a curator asks about** — a table row, a plate legend, a paragraph — not as an arbitrary 256-token window. | 6,041 blocks → **2,902 chunks**: 1,341 table rows, 97 table headers, 96 figure/plate units, 1,368 prose windows. 384-d vectors, 765 pages covered. | `BAAI/bge-small-en-v1.5` (384-d). BGE-M3 (1024-d, 2.2 GB) was A1's plan and is 6× the memory for a corpus of 2,902 chunks; the small model keeps the whole index memory-resident and CPU-rebuildable. FAISS **HNSW** (M=32, efC=200, efS=64), inner product on L2-normalised vectors = cosine. | **Structure-aware chunking (the declared bonus):** a table becomes one chunk per ROW with the header row carried on every row; prose packs to 256 tokens on paragraph bounds with 32-token overlap under its heading; a plate's caption and labels form one unit. `index.chunking: fixed` gives the flat baseline for comparison. | Chunk ids are `{page_id}_c{nnn}` and stable, so A3's gold labels can point at them. Chunks are persisted as JSONL beside the vectors, so a citation resolves without a database. | `kb_demo.ipynb` §4 shows both chunkers on the same page; §5c measures HNSW recall@5 = 1.000 against exact flat search, so the approximation is measured rather than assumed. Vectors are cached by a hash of the chunk texts — a config change that does not touch text is free. | Index build is 0.1 s over 2,902 vectors; the whole pipeline is one command (`scripts/build_index.sh`). Memory-resident, CPU. | `meta.json` records embed checkpoint, dim, index params, chunking mode, reader, layout model, seed and build time. An index whose provenance is unknown cannot be reproduced. |
| **5 Retrieval** | Return the chunks that actually support an answer, and produce a score that *means* something so weak evidence can be detected. | The 2,902-chunk index; A3 adds `grading_kit/tasks.jsonl`. | Dense bi-encoder (as above) + `BAAI/bge-reranker-base` cross-encoder over the top candidates. | Cosine top-k, then rerank. `k` starts at 10 and widens by `k_step` on weak evidence to `k_max` = 40. | Hybrid dense + lexical is the A3 addition: `kb_demo.ipynb` §6 shows the concrete failure that forces it — fourteen near-identical quarry tables whose top-5 scores span 0.011. | A2 already exercises the retrieval path inline (§5). A3 moves it into `retrieval/retriever.py` and measures recall@k. | Query-time, CPU, sub-millisecond at this corpus size. | Query, ranked list and scores logged per answer for the A3 audit trail. |
| **6 Agent** | Perceive → decide → act → answer, grounded and cited, abstaining when the evidence is not there. | Retrieved chunks + page crops. | Frozen instruction-tuned VLM as the answerer — deliberately **not** fine-tuned on palaeontology: a model that already knows the answer can produce it without evidence. | Rule-based ReAct loop with the mandatory **evidence-gated re-search**: `top_score < weak_threshold` ⇒ widen `k`, re-retrieve, abstain at `k_max`. | Loop and tool names are fixed by the repo; we implement `decide()`, `act()`, `synthesize()`. Read-only autonomy: the only acting tool is `escalate_to_human`. | A3 authors the `{needs_research: true/false}` task pair that proves re-search fires only when needed. | FastAPI + Gradio in A4. | `traces/run.jsonl`, one `TraceStep` per step. |

Learn tool choice under budget; reward verifiable extractions. | The verifiable subset of `tasks.jsonl`. | GRPO/RLVR over the rule-based policy. | Reward = correct checkable answer, correct abstention, citation box on the right row; penalty for answering under the evidence gate. | Secondary to our declared semantic-chunking bonus. | Only attempted if the core build is green. | n/a | W&B run per training job. |
| **8 Serving** | Give the curator the answer **and the pixels**, so it can be checked. | The built index + original page rasters. | — | FastAPI `/answer` + Gradio page viewer that draws `bbox_norm` over the **original** greyscale scan. | Citations point at pixels, not just page numbers — which is why Stage 1 never overwrites the greyscale page. | A4. | HF Spaces + Docker; the lockfile and Dockerfile are already in the repo. | Model registry entry per shipped checkpoint. |

## The three decisions we would defend hardest, with what they cost

**1 · No generative enhancement — and that is a measurement, not laziness.**
A1 left VAE/diffusion scan repair open. We measured before buying: median text-page skew 0.00°, only
1.0% of text pages above the deskew gate, and 0.9% actually rotated. Generative repair would invent
pixels on 99% of a corpus that does not need them — and we would then be asking a curator to cite
invented pixels. *Cost:* the faintest Leidy pages stay under-restored. *What would change it:* if
reading quality on Leidy trailed Colbert by more than 10 points. It does not — Leidy's CER is 4.46%
against Colbert's 5.89%, because Leidy's difficulty is faintness, which Sauvola handles, not
structure, which it does not.

**2 · Structure-aware chunking over a fixed window (the declared bonus) — with a measured downside.**
One chunk per table row, header carried. On the same page a fixed window produces 3 chunks of ~170
tokens; ours produces 38 units of ~22, and the unit *is* the answer. The cost is real and we found it:
Gilmore prints the same four-column quarry table fourteen times, so row chunks become near-identical
documents and a bi-encoder cannot separate them — top-5 scores within 0.011, gold page at rank 3
(`kb_demo.ipynb` §6). We are not tuning that away on the eve of submission, because the fix (put the
caption on the row) and the mitigation (cross-encoder rerank) belong in A3 where they can be measured
against a task suite instead of against the page we just looked at.

**3 · A heuristic layout detector over the DocLayout-YOLO we named in A1.**
A pretrained detector trained on modern born-digital documents has no notion of a 1914 lithographic
plate or a dot-leader measurement table, and fine-tuning it needs region labels for this corpus that we
do not have. The heuristic's thresholds come from distributions measured on these 904 pages, and it
runs in 0.1 s/page on CPU with no labels at all. *Cost:* it over-fires on numbered lists (a prose page
with a numbered list has a table's row geometry) — recorded as a known false positive in the demo
notebook rather than tuned away on held-out data. *What would change it:* enough hand-labelled regions
to fine-tune, which is an A3 data-collection decision, not an A2 one.
